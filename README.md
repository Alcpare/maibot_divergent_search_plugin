# 发散搜索结果（Alcpare.divergent_search）

给麦麦提供**联网搜索**能力，基于百度千帆 AI Search。

- 当前版本：**1.0.0**
- 兼容：MaiBot ≥ 1.3.19 / 插件 SDK ≥ 2.9.0
- 联系方式：**1373558257@qq.com**

---

## 这个插件解决什么问题

麦麦需要查实时信息（新闻、价格、版本号）时，通常两种结果都不理想：

1. **不知道就说不知道** —— 明明能查，却答不上来；
2. **把搜索原文整段念出来** —— 用户看到一堆标题、链接、条目，像是粘贴了一份报告。

本插件在搜索结果后面**追加一段可编辑的提示词**，告诉模型「这是参考资料，不是你要说的话，
用你自己的口语挑一两点说出来」。插件里还附带日志，能看到每次注入了什么。

## 一、安装

### 1. 装插件

放进 `plugins/Alcpare_qianfan_search/` 目录，或在 WebUI 插件市场搜索「发散搜索结果」安装。

### 2. 填 API Key（必填）

去 [百度千帆控制台](https://console.bce.baidu.com/qianfan/) 申请 API Key（`bce-v3/ALTAK-...` 格式），
然后在 WebUI 插件配置的「接口 → API Key」里填进去。

**没有 Key 时插件不会崩**：搜索工具会返回「搜索不可用，直接说不知道。」，麦麦照常聊天。

### 3. 重启或热加载

保存配置后热加载即可，不用重启。

## 配置项

### 接口

| 配置项 | 默认 | 说明 |
|---|---|---|
| `api_key` | 空 | 千帆 API Key，必填 |
| `base_url` | `https://qianfan.baidubce.com` | 接口地址，一般不用改 |
| `timeout` | 30.0 | 单次请求超时（秒） |
| `retry` | 1 | 失败重试次数（只对 5xx/超时重试，4xx 不重试） |

### 搜索结果

| 配置项 | 默认 | 说明 |
|---|---|---|
| `max_results` | 3 | 返回几条结果 |
| `preview_chars` | 260 | 每条正文截取多少字 |
| `include_url` | true | 是否附带来源链接 |
| `dedupe` | true | 是否按标题/正文去重 |

### 工具与提示词

| 配置项 | 默认 | 说明 |
|---|---|---|
| `tools.enable_search` | true | 是否向模型提供 `web_search` 工具 |
| `tools.search_description` | (见配置) | 告诉模型什么时候该用这个工具 |
| `prompt.enabled` | true | 是否在搜索结果后追加提示词 |
| `prompt.after_search` | (见配置) | **可编辑**的追加提示词 |

**`prompt.after_search` 是这个插件的核心。** 默认内容是：

```
（以上是搜索结果，不是你说的话。你要做的是：把里面跟当前聊天有关的一两点，
用你自己的口语说出来，别念标题、别列条目、别贴链接、别说「根据搜索」。
没用的就别提，一句带过也行。）
```

改这段话就能调整麦麦转述搜索结果的方式。

## 它到底给模型看什么

模型收到的工具返回长这样：

```
搜索结果（查询词）：
1. 标题（发布时间）
   正文摘要（截取 260 字）
   来源：https://...
2. 标题（发布时间）
   ...

（以上是搜索结果，不是你说的话。……）
```

末尾那段就是 `prompt.after_search`。

## 设计要点

| 点 | 说明 |
|---|---|
| **错误不外泄** | 无 key / 超时 / HTTP 错误 / JSON 异常，模型只会看到固定文案（如「搜索不可用，直接说不知道。」），看不到内部错误细节 |
| **缓存** | 同一查询 `cache_seconds` 内直接返回，默认 60 秒 |
| **去重** | 按标题前 40 字 + 正文前 80 字去重，避免同一篇文章重复占位 |
| **并发安全** | 全局锁串行化请求，避免同时打爆接口 |
| **重试策略** | 只对 5xx 和超时重试，4xx（如 key 错误）不重试 |
| **无 key 降级** | 不填 key 插件照常加载，只是搜索工具不可用 |

## 常见问题

**Q：填了 key 但搜索一直失败？**

先看日志里 `key=已填` 还是 `key=未填`。再看返回的固定文案是什么：
- 「搜索不可用」→ key 没读到
- 「搜索超时」→ 网络问题，可以调大 `timeout`
- 「搜索出错」→ 接口返回异常，检查 key 是否有效/是否欠费

**Q：搜索结果太长，撑爆上下文？**

调小 `max_results`（比如 2）或 `preview_chars`（比如 150）。

**Q：她还在念搜索结果怎么办？**

改 `prompt.after_search`，把话说得更硬。默认那段已经明确说了「别念标题、别列条目、别贴链接」。
如果还不行，说明是模型本身不听话，可以考虑关掉 `prompt.enabled` 外的其他手段。

**Q：能和 MaiBot 内置的联网搜索共存吗？**

可以，但建议只留一个。内置的走 `model_task_config.web_search`，本插件走工具，两者同时开会重复。

## 更新日志

### v1.0.1
- **修复 	ools.enable_search 不生效**：此前该开关只用于启动日志，关掉后搜索工具照样联网。
  现在改为运行时判断——关闭时 web_search 直接返回「搜索已关闭，直接说不知道。」，不发起任何请求。

  留着会误导。搜索工具的描述固定为内置文案。
- 配置项说明补上准确行为，避免改了没反应的困惑。
